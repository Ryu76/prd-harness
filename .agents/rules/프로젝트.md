# PRD Harness - 프로젝트 지침 (MCP 활용 및 보안)

이 지침은 `prd-harness` 프로젝트에서 Antigravity 에이전트가 코딩 작업을 수행하거나 외부 MCP 서버와 상호작용할 때 반드시 준수해야 하는 규칙입니다.

## 1. 외부 MCP 서버 활용 원칙
현재 프로젝트는 자동화된 PRD 실행 환경을 구축하고 있습니다. 다음 MCP 모듈 연동 시 아래 규칙을 따릅니다.

*   **GitHub / GitLab MCP (컨텍스트 확장)**: 작업 지시서(PRD) 내에 이슈 번호나 관련 PR 링크가 존재한다면, 코드를 수정하기 전 반드시 MCP를 통해 해당 이슈의 디스크립션과 논의 내역을 읽고 누락된 요구사항이 없는지 확인해야 합니다.
*   **Slack / Discord MCP (Hermes 관제)**: 하네스 데몬에서 작업이 `TEST_FAILED` 또는 `BLOCKED` 등 비정상 상태로 종료될 위기에 처하면, 에이전트는 해당 MCP를 활용하여 사용자에게 즉각적인 실패 사유와 로그 요약을 알림으로 전송해야 합니다.
*   **Database MCP (읽기 전용 제한)**: 하네스의 `allow_db_change: false` 보안 규칙을 엄격히 적용합니다. 데이터베이스 MCP가 연결되어 있더라도 쿼리 실행이나 스키마 변경(`INSERT`, `UPDATE`, `DROP`, `ALTER` 등)은 절대 수행해선 안 되며, 오직 테이블 구조 조회를 위한 읽기 전용(`SELECT` 등 스키마 분석)으로만 활용합니다.

## 2. 프로젝트 보안 및 제약 사항
*   **API 키 은닉**: 어떠한 경우에도 소스 코드나 텍스트 결과물에 `GEMINI_API_KEY`, `OPENAI_API_KEY` 등을 평문으로 작성하거나 주입해서는 안 됩니다.
*   **자동 반영 금지**: 코딩 작업이 성공적으로 끝나더라도 절대 자동 `git commit`이나 `git push`를 수행해선 안 되며, 모든 결과물은 사람이 검토할 수 있도록 `diff` 형태로 남겨두고 `READY_FOR_REVIEW` 상태로 종료합니다.
*   **실행 환경 인지**: 이 프로젝트의 에이전트는 `agy_executor.py`를 통해 `--dangerously-skip-permissions` 플래그가 켜진 상태로 동작할 수 있습니다. 따라서 권한 확인 프롬프트가 뜨지 않는 자동화 상태임을 인지하고, 시스템을 훼손할 수 있는 위험한 스크립트 실행을 자체적으로 차단해야 합니다.
